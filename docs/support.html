平台支持

NoldOJ CLI 使用 C++17 编写，网络层按平台选择：Windows 使用系统 WinHTTP，Linux、macOS 与 Android Termux 使用 libcurl。

已验证的环境

CI 在 GitHub Actions 上使用 ubuntu-24.04（Linux x64）和 windows-2022（Windows x64）编译并执行端到端测试；其余平台在发布时构建，不运行测试。

依据为发布产物的二进制元数据：PE 子系统版本与导入表、readelf -V 符号版本、Mach-O LC_BUILD_VERSION。

构建命令

Windows x64 / x86 / arm64

# x64（MinGW 或默认工具链）
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build

# x86（MinGW32）
cmake -S . -B build -G Ninja -DCMAKE_CXX_FLAGS=-m32

# arm64（Visual Studio 2022）
cmake -S . -B build -G "Visual Studio 17 2022" -A ARM64
cmake --build build --config Release

Linux x64 / x86 / arm64

# x64 / arm64（原生，自动链接 libcurl）
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build

# arm64 交叉编译
cmake -S . -B build -G Ninja \
  -DCMAKE_CXX_COMPILER=aarch64-linux-gnu-g++

# x86（32 位）交叉编译
cmake -S . -B build -G Ninja \
  -DCMAKE_CXX_COMPILER=i686-linux-gnu-g++

macOS x64 / arm64

# 本机架构（Apple Silicon 为 arm64，Intel 为 x64）
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build

# 指定架构
cmake -S . -B build -G Ninja \
  -DCMAKE_OSX_ARCHITECTURES=arm64
cmake -S . -B build-x64 -G Ninja \
  -DCMAKE_OSX_ARCHITECTURES=x86_64

# 使用 Homebrew 的 curl（可选）
cmake -S . -B build -G Ninja -DCMAKE_PREFIX_PATH=$(brew --prefix curl)
macOS 系统自带 libcurl 与头文件（位于 Xcode Command Line Tools 的 SDK 中），通常无需额外安装依赖。

Android / Termux（arm64）

pkg install cmake ninja libcurl pkg-config
cmake -S . -B build -G Ninja -DCMAKE_PREFIX_PATH=$PREFIX
cmake --build build

Android NDK

cmake -S . -B build -G Ninja \
  -DCMAKE_TOOLCHAIN_FILE=$NDK/build/cmake/android.toolchain.cmake \
  -DANDROID_ABI=arm64-v8a
NDK 不自带 libcurl，使用 NDK 交叉编译时需自行提供 libcurl（例如通过 vcpkg 或预编译产物），并通过 CMAKE_PREFIX_PATH 指定。

测试

测试脚本为纯 Python 3 实现，不依赖第三方库，会在本地启动 HTTP 回显服务并验证真实请求。

python tests/run_tests.py build/noldoj
python tests/run_tests.py build/noldoj.exe   # Windows

覆盖范围：版本输出、帮助信息、auth tokeninfo、查询参数、JSON 请求体、自定义请求头、--include、stdin 请求体、404 错误处理与配置路径。

常见问题

提示“未指定站点”

首次使用需要先添加站点：noldoj site add --name main --url https://your-oj/api/v1 --token <PAT>，之后可用 noldoj site use --name main 设为默认站点。

连接失败或证书错误

确认 --site 的地址包含正确的协议（https/http）与 /api/v1 前缀。Windows 使用系统证书存储，Linux/Termux 使用 libcurl 默认 CA；自签证书请在系统中安装根证书。

接口返回 401 / 403

使用 noldoj auth tokeninfo 检查令牌类型、权限范围与到期时间。私人令牌需要具备对应 scope：读取需要 read，提交需要 submit，写操作需要 write，修改本人资料等 /users/me 写操作需要 account。此外 auth change-password、user sudo-login、user reset-password 只接受登录会话（JWT），私人令牌无法调用，CLI 会在本地直接提示改用网页端。

Termux 中无法找到 libcurl

执行 pkg install libcurl pkg-config，并确保配置时传入 -DCMAKE_PREFIX_PATH=$PREFIX。

Windows 控制台中文乱码

程序启动时会设置 UTF-8 输出代码页。若使用旧版控制台，建议改用 Windows Terminal 或 PowerShell 7。
